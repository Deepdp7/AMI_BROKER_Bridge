0. THE PROJECT IN 30 SECONDS (read this first)
-------------------------------------------------------------------

  apps/server     = the "engine" (Node + TypeScript). Talks to brokers, stores bars, serves everything.
                    HTTP API on port 7890. AmiBroker plugin talks to it on port 7891.
  apps/desktop    = the app window (Tauri + React). Only talks to the engine's API.
  plugins/        = small native add-ons that live inside other programs
                    (amibroker = C++ plugin DLL, excel = C++ RTD DLL, metatrader5 = .mq5 service).

  Data is stored in SQLite:  %APPDATA%\DataBridgePro\databridge.db
  Prices are stored x10000 as whole numbers, time in seconds (UTC).
  Broker logins are encrypted with %APPDATA%\DataBridgePro\secret.key (Windows DPAPI).

1. NEW BROKER: KOTAK NEO                                  (commit 2e06fe2)
-------------------------------------------------------------------

  What it does: Kotak Neo can now be connected like the other brokers (15 brokers in total now).

  Step by step:
   1. Login = mobile number + authenticator code (TOTP) + MPIN.
      The user can type the 6-digit code OR paste the authenticator secret key;
      with the key the engine makes the code itself (apps/server/src/lib/totp.ts).
   2. The app packs those details into ONE secret and sends it with the client code
      (apps/desktop/src/pages/BrokerConnection.tsx).
   3. Symbol list: read from Kotak's public files, renamed to the same ticker names
      every other broker uses (kotak/KotakInstruments.ts).
   4. Live prices: Kotak's binary socket (kotak/KotakFeed.ts). A refused login ends
      in "auth_failed", never a fake "connected".
   5. History: fixes Kotak's bad bars (open outside high/low, negative volume).

  Files:  apps/server/src/brokers/adapters/kotak/*   tests: apps/server/tests/kotak.test.ts

8. BIG BUG: FYERS LIVE PRICES SILENTLY STOPPED           (commit 83ab998)
-------------------------------------------------------------------

  What happened:
   - Fyers' live socket answers the login with message type 1 whether it accepted or not.
     The reply text is "K" when accepted, or the reason, e.g. "authentication failed".
   - Our code only checked the type, logged "Auth successful", subscribed, Fyers dropped
     the connection, and we reconnected every 6 seconds all day. No live prices.
   - History (REST) still worked with the same token, so AmiBroker still got bars,
     which hid the problem.

  The fix:
   1. Read the reply text (hsmAuthAnswer in FyersHSMClient.ts).
   2. Refused once -> try one more time.
   3. Refused twice -> stop, log "Live prices stopped: log in to Fyers again in Broker
      Connection", and emit "auth_failed" so the app shows "log in again".
   4. Every disconnect is now written to the log with its reason code.

  Note: the stored price data was checked against Fyers' own history service and matched exactly.
  Nothing was ever changed or invented in prices.
  -> apps/server/src/brokers/adapters/fyers/FyersHSMClient.ts, tests/fyersAuth.test.ts

10. "1 DAY MISSING" FALSE ALARM ON ILLIQUID FUTURES      (commit 1758ca3)
-------------------------------------------------------------------

  Example: FORTIS26NOVFUT showed "Missing: 2026-09-03".
  Reason: that contract had zero trades that day (the market was open; FORTIS stock traded).
  No broker has data for a day with no trades, so "Repair" could never fill it.

  The fix:
   1. When a broker's history has bars before and after a weekday but none on it, that day
      is remembered as a "quiet day" for THAT symbol only
      (saved in %APPDATA%\DataBridgePro\closed_days.json, key "quiet").
   2. The history check (DataHealth.ts) does not count quiet days as missing,
      so "Repair all" doesn't queue them either.
   3. If bars for that day show up later, it stops being a quiet day.
   4. Old closed_days.json files are read too, so nothing needs re-downloading.
  -> apps/server/src/market/MarketCalendar.ts (isQuietDay), market/DataHealth.ts

11. HOW TO TEST AND BUILD
-------------------------------------------------------------------

   Engine tests:      cd apps/server   ->  npx vitest run        (318 tests, all pass)
   Engine types:      cd apps/server   ->  npm run typecheck
   App tests:         cd apps/desktop  ->  npx vitest run        (136 tests, all pass)
   App types:         cd apps/desktop  ->  npm run typecheck     (and npx tsc -b)
       !! In apps/desktop, plain "npx tsc --noEmit" checks NOTHING. Use the commands above.

   Build for users:
     1. Close AmiBroker (it locks the plugin DLL).
     2. npm run build:files
     3. Build the installer (Installer Studio -> Build installer).
     4. In the app: Platforms -> Excel -> "Reinstall live prices" (new Excel connector).

12. RULES / TRAPS TO KNOW
-------------------------------------------------------------------

   - Port 7890 = the real engine, 7891 = AmiBroker plugin. Run test servers on 17890.
   - Never put passwords or tokens in code, logs or notes. The database and secret.key
     contain broker logins: if you copy them for testing, delete the copy afterwards.
   - Tests run in their own temp folder (they set USERPROFILE/HOME/DATABRIDGE_DB_PATH);
     never point a test at the real %APPDATA%\DataBridgePro.
   - Fyers tokens expire every day at 06:00 India time.
   - Don't kill or Quit the user's own Excel from code or tests.
